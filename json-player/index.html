This page uses two formats: a structured one (first), which allows hierarchies of parameters (frequency, volume, time scale, time displacement, decay factor, attack time), and a flattened one, used when playing. But you don't have to worry with the flattened one until the last moment.

The formats are based on an existing one, called JSON. The basic generic syntax for an object is: {"property1": value1, "property2": value2, ...}. Another one is [value1, value2, ...], when the values are indexed by natural numbers starting from zero (those objects are called arrays). That would be the same as {"0": value1, "1": value2, ...}.

Block (inheritable) properties are: freqRatio, volRatio, timeDelta, tempo, decayFactor, attack.

Note properties are (most of them relative):

noteStart
The moment in time the note is played.
noteStop
The moment in time the note is silenced.
duration
The amount of time the note plays. (You don't need both noteStop and duration—they are redundant.)
freq
Frequency.
vol
Amplitude.
decayFactor
How slowly the note amplitude is dampened while still playing (absolute).
attack
How slowly the note amplitude comes (absolute).

Frequencies, tempo and duration support several number formats:

  • 1.25 = 1.25
  • "1.25" = 1.25
  • "5/2/2" = 5/4 = 1.25
  • [-2, 0, 1] = 2-2 * 30 * 51 = 5/4 = 1.25 (uses prime factors implicitly)
  • {"2": -2, "5": 1} = 2-2 * 51 = 5/4 = 1.25 (great for use with prime factors)
