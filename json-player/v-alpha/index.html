This tool presumes understanding about mathematics, acoustics, basic computer usage and some musical theory. Some exposure to programming and data types will also help. Here we try to bypass the unreasoning junk and thick tradition associated with the field of music, and relate to a more scientific view of the gist of the subject. This tool encourages just intonation via prime factors and fractions as the ultimate way to control consonance, and prime factor analysis for rhythmic structure and harmony.

This page uses two formats for music representation: a structured one (first), which allows deep hierarchies of parameters (see the properties below), and a related "flattened" one (non-recursive list of notes), used when playing, supporting only note properties. But you don't have to worry with the flattened one until the last moment (see the principle of abstraction, What You See Is What You Mean). As it is a text format, it becomes easy to perfectly (manually) save and load content.

Though the page is novel, the formats are based on an existing one, called JSON (JavaScript Object Notation, a computer language). The basic generic syntax for a structure node is: {"property1": value1, "property2": value2, ...} (known as an object). As in many computer languages, usage of alphabetic characters is case-sensitive and names are strict. Another syntax is [value1, value2, ...], when the values are implicitly indexed by natural numbers starting from zero (those objects are called arrays or lists). That would be the same as {"0": value1, "1": value2, ...}.

The structured representation is made to be readable and editable, while also understandable by a computer. In this format, you must use numerical indices (explicitly or not) to attach structures (i.e. patterns, subnodes; whether notes or blocks of notes) that should be played; you can use names (quoted strings) for node reuse, but for them to be played, they must be instantiated under a numerical index (e.g. "0": "myPattern", "myPattern": {...}). Use natural numbers starting at 0 and don't skip numbers. Their order can be arbitrary; the indices don't tell anything about note time. You can observe about proper usage of the format by using the generators; otherwise, we suggest using a code editor for increased productivity. Currently there is no special circular reference prevention, so circular references may freeze parsing.

Eventually, the structured representation is converted (by the page) into the flattened representation, which is easier for the computer to play. In it, blocks, recursion, named patterns, numerical structures and arithmetics are not available. For human interaction (reading and editing), prefer the structured format; the flattened representation is only needed when the computer is to play the music.

Block (inheritable) properties are:

freqRatio (multiplicative, default 1)
Can be used both for pitch tuning and interval accumulation.
volRatio (multiplicative, default 1)
Can be used to compensate for polyphony (like the generators do).
timeDelta (additive, default 0, relative to timeScale)
Relative time position or delay.
timeScale (multiplicative, default 1)
Inverse of tempo/speed.
timbre (substitutive, default "sine")
decayFactor (substitutive, default 256)
attack (substitutive, default "1/64")
portamento (substitutive, default 0)
vibratoFreq (substitutive, default "2^18 / 86400" = ~3.034)
vibratoDepth (substitutive, default 0)
vibratoAttack (substitutive, default 3)

Note properties are (influenced by block properties, and most of them relative factors):

noteStart (default noteStop of previous note or 0)
The moment in time the note is played.
Affected by timeDelta, timeScale, overall time delta and overall time scale.
noteStop (default noteStart + duration)
The moment in time the note is silenced.
Affected by timeDelta, timeScale, overall time delta and overall time scale.
duration (default 1)
The amount of time the note plays. (You don't need both noteStop and duration—they are redundant.)
Affected by timeScale (and overall time scale).
freq (default 1/always required in flattened list)
Frequency, which represents pitch.
Affected by freqRatio and overall frequency scale.
vol (default 1)
Amplitude, which represents volume.
Affected by volRatio and overall volume scale.
timbre (default "sine")
Waveform used in synthesis (comparable to a musical instrument). Can be "sine" (narrow-band) or "noise" (wide-band).
Absolute override when present.
decayFactor (default 256)
Sustain time factor (how slowly the note amplitude is dampened while still playing); more precisely, decay half-life = decayFactor / freq.
Absolute override when present, but always affected by overall time scale.
attack (default "1/64")
Amplitude envelope attack half-life (how slowly the note amplitude comes at its beginning).
Absolute override when present, but always affected by overall time scale.
portamento (default 0)
When different from zero, it is the half-life of the initial pitch transition into the actual note pitch (portamento). When zero, portamento is disabled and pitches are abrupt.
Absolute override when present, but always affected by overall time scale.
freq0 (default last note frequency, 0 initially)
If portamento is enabled, this is the initial frequency. A 0 value disables portamento.
Note-only property, not retained by blocks.
vibratoFreq (default "2^18 / 86400" = ~3.034)
Frequency for pitch modulation.
Absolute override when present.
vibratoDepth (default 0)
Variation scale for pitch modulation: between -vibratoDepth and +vibratoDepth octaves.
Absolute override when present.
vibratoAttack (default 3)
Half-life of the onset of pitch modulation effect (how slowly the effect fades in).
Absolute override when present, but always affected by overall time scale.

In the structured representation, block and note properties support several number formats. Examples:

  • 1.25 = 1.25 (literal number)
  • "1.25" = 1.25 (text to number)
    • "5*0.5*0.5" = 5/4 = 1.25
    • "5/2/2" = (5/2)/2 = 5/4 = 1.25
    • "5/2^2" = 5/(2^2) = 5/4 = 1.25 (^ denotes exponentiation)
  • [-2, 0, 1] = 2-2 × 30 × 51 = 5/4 = 1.25 (uses prime factors implicitly)
    • String expressions are supported in object values: ["-1-1", 0, 1] = [-2, 0, 1]
  • {"2": -2, "5": 1} = 2-2 × 51 = 5/4 = 1.25 (great for use with prime factors, but also supports other factors)
    • Even factors can be string expressions: {"2": -2, "2 + 3": 1} = {"2": -2, "5": 1}
  • To emulate twelve-tone equal temperament, use powers of 2 (octave) with a number of semitones divided by 12 (fraction of an octave) as exponent. E.g. ["7/12"] = 27/12 would represent a fifth interval (7 semitones).

Rules for strings:

  • For expressions with operators, quote them as text.
  • Subexpressions inside parenthesis are evaluated first.
  • As in many computer languages, the text symbols for multiplication, division and exponentiation are (respectively) *, /, ^.
  • Operator precedence: ^ (first), /, *, -, + (last)
  • Addition, multiplication and exponentiation are right-associative: e.g. 4^3^2 = 4^(3^2), not (4^3)^2
  • Subtraction and division are left-associative: e.g. 4 - 3 - 2 = (4 - 3) - 2, not 4 - (3 - 2)

Currently, there are no features about rewrite rules (other than simply named nodes), custom synthesis (only sine waves and noise are played), custom filtering, custom effects, custom mixing pipeline or spatialization.
